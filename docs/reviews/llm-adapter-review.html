1. 架构总览

架构优点

  • 分层清晰 — 核心抽象层（types/base/transform/streaming/retry）与 Provider 实现层完全分离，新增 Provider 只需实现 ILLMAdapter 接口
  • 装饰器模式 — ResilientLLMAdapter 以组合方式包装任意 Provider，retry 和 circuit breaker 可独立开关
  • 纯函数转换 — transform.py 全部是无副作用纯函数，天然可测试，Provider 之间共享逻辑不重复
  • 统一类型系统 — content 永远是 ContentBlock 数组，消除了 OpenAI string|array 二义性，上层代码无需关心 Provider 差异
  • 工厂函数 — create_adapter() 通过字符串映射动态导入 Provider，上层代码零耦合

2. 数据流分析

非流式请求路径

1
resilient.create_adapter() — 工厂函数根据 provider 名称动态导入 Provider 类，创建 ResilientLLMAdapter 实例
↓
2
ResilientLLMAdapter.complete() — 检查 CircuitBreaker 状态 → 调用 retry_with_backoff() 包装内部 Provider
↓
3
Provider._build_request_body() — 调用 messages_to_openai/deepseek/anthropic() 转换消息格式，附加采样参数
↓
4
httpx.AsyncClient.post() — 发送 HTTP 请求，网络异常转为 ServiceUnavailableError
↓
5
Provider._handle_error() + _parse_response() — HTTP 状态码映射到 RateLimitError / InvalidRequestError，响应体通过 parse_openai/anthropic_response() 转回统一类型
↓
6
ResilientLLMAdapter — 记录成功/失败到 CircuitBreaker，返回 CompletionResult

流式请求路径

1
ResilientLLMAdapter.stream() — 检查 CircuitBreaker → 调用 retry_with_backoff() 获取 AsyncIterator[StreamEvent]
↓
2
Provider.stream() — httpx.stream("POST") 建立 SSE 连接，parse_sse_lines() 逐行解析为 JSON dict
↓
3
OpenAIStreamParser / AnthropicStreamParser — 维护增量拼接状态（tool_calls buffer / content_block index），每个 chunk 转为 StreamEvent 列表
↓
4
StreamCollector (可选) — 消费端使用 feed() 累积事件，最终 collect() 得到完整 CompletionResult

数据流 — 设计亮点与已知限制

  • 错误提前转换 — Provider 在收到非 200 响应时立即抛出 typed 异常（如 RateLimitError），retry 层按 retryable 字段决策，不需要解析原始错误
  • 流式重试风险 — ResilientLLMAdapter.stream() 通过 retry 包装，但流一旦开始 yield 就无法重试。retry 只作用于"建立连接"阶段，中途断流不重试
  • Anthropic 双解析器 — Anthropic 流式事件类型远多于 OpenAI（message_start/content_block_start/delta/stop），需要独立的 AnthropicStreamParser 维护 index → block 映射

3. 各模块分析

types.py
统一类型系统 — 所有模块的基础
定义了完整的消息/内容块/工具/配置/结果/流式事件类型体系。设计决策：content 永远是 ContentBlock 数组（消除 OpenAI string|array 二义性），ToolMessage 独立 role（内部用独立 role，转换时按目标格式合并）。

亮点：ThinkingBlock 预留了 signature 字段（Anthropic 回传校验），ThinkingConfig 用 budget_tokens 区分 provider 能力。provider_extras 字典允许上层透传各家特有参数，不污染统一接口。
257 lines
base.py
ILLMAdapter 抽象接口 + 异常层次
ABC 定义 4 个方法：complete / stream / get_provider_info / health_check。异常体系为 4 层继承：LLMAdapterError → RateLimitError / ServiceUnavailableError / InvalidRequestError / CircuitOpenError，每个异常自带 retryable 标记。

亮点：retryable 让 retry.py 不需要理解 HTTP 状态码，只看异常类型。health_check 为 circuit breaker 提供探测入口。
160 lines
transform.py
消息格式双向转换 — 最大的核心模块
纯函数集合，负责内部统一格式 ↔ OpenAI/DeepSeek/Anthropic 三家格式互转。按目标分三组：messages_to_openai/deepseek/anthropic()（请求方向）、parse_openai/deepseek/anthropic_response()（响应方向）、tools_to_openai/anthropic()（工具定义）。

亮点：normalize_messages() 在发送前做三件事 — tool_use/tool_result 配对补 "(cancelled)"、同角色合并、协议字段保留。messages_to_anthropic() 处理了 Anthropic 最棘手的 system 分离 + 严格交替要求。

注意：586 行是模块中最大的文件，但全是纯函数、无状态，复杂度可控。
586 lines
streaming.py
SSE 解析 + 流式事件收集
三层设计：parse_sse_lines() 通用 SSE 行解析器（过滤 data: 前缀、处理 [DONE]）；OpenAIStreamParser 维护 tool_calls 增量拼接状态；StreamCollector 提供 text_stream / collect 两种消费方式。

亮点：OpenAIStreamParser 用 index → buffer dict 处理多个并行 tool call 的增量拼接，finish_reason 时输出完整 TOOL_USE_END 事件。StreamCollector.get_text_so_far() 支持实时预览已收集文本。
293 lines
retry.py
重试策略 + Circuit Breaker
重试：retry_with_backoff() 实现指数退避 + jitter + retry-after 优先。should_retry() 按 retryable 标记决策，400 错误立即失败。

Circuit Breaker：经典三态机 CLOSED → OPEN → HALF_OPEN。连续 N 次失败触发熔断，冷却期后允许探测，探测成功 M 次恢复。state property 自动检查是否该进入 HALF_OPEN（惰性转换，无需定时器）。

亮点：数据驱动设计，RetryConfig / CircuitBreakerConfig 均为 frozen dataclass，所有策略参数可配置。get_stats() 暴露监控数据。
257 lines
resilient.py
门面层 — 工厂函数 + 弹性包装器
ResilientLLMAdapter 组合 Provider + RetryConfig + CircuitBreaker，对外实现 ILLMAdapter 接口。每个方法先检查断路器，再通过 retry_with_backoff 委托给内部 Provider。

create_adapter() 工厂函数通过 _PROVIDER_MAP 字符串映射动态导入 Provider 类，上层代码只需传 provider 名称。

亮点：装饰器模式 — 可以多层包装（理论上可以 retry-on-retry），Provider 实现完全不知道 retry/circuit breaker 的存在。
146 lines
openai_provider.py
OpenAI ChatCompletions Provider
最标准的 Provider 实现。_build_request_body() 调用 messages_to_openai() + tools_to_openai() + build_openai_sampling_params()。流式使用 OpenAIStreamParser。

特点：支持 reasoning_effort（o 系列）、provider_extras 透传。不支持 reasoning_content（o 系列隐藏思考）。
241 lines
deepseek_provider.py
DeepSeek V4 Provider (OpenAI 兼容接口)
复用 OpenAI 框架但有关键差异：messages_to_deepseek() 保留 reasoning_content 字段（tool call 场景必须回传，否则 400）；_validate_no_image_blocks() 拒绝视觉输入；thinking 模式下 temperature/top_p 静默无效（发出 warning）。

亮点：reasoning_effort 只接受 "high"/"max"，自动映射非法值。
288 lines
anthropic_provider.py
Anthropic Messages API Provider
协议差异最大的 Provider。system 是顶层字段、tool_use/tool_result 是 content block、arguments 是 object。需要独立的 AnthropicStreamParser 处理 message_start / content_block_start / delta / message_delta 多层事件。

特点：Extended thinking 支持 budget_tokens + signature 回传。_build_request_body() 自动计算 max_tokens（必须 ≥ budget + 输出）。支持 cache_control / pdf / computer_use 通过 provider_extras。

亮点：最复杂但最完整 — 394 行覆盖了 Anthropic 的所有关键差异点。
394 lines
__init__.py
模块入口 — 统一导出
从 base / resilient / types 三处导出所有公开 API。__all__ 列表完整（38 个符号），按功能分组。上层代码只需 from agent_framework.llm import create_adapter, CompletionConfig。

MEDIUM 待改进 流式请求的 retry 语义不完整
resilient.py:55-69
ResilientLLMAdapter.stream() 通过 retry_with_backoff() 包装，但 retry 只作用于"建立 SSE 连接"阶段。一旦连接建立并开始 yield 事件，中途断流不会被重试。

retry_with_backoff 期望 fn 返回最终值，但 provider.stream() 返回 AsyncIterator。retry 在拿到 iterator 后立即返回，真正的流式消费发生在 retry 之外。
改进方向： 方案 A：明确文档说明 retry 只覆盖连接建立阶段（最简单）。 方案 B：stream() 不走 retry_with_backoff，只在连接失败时手动重试。
MEDIUM 待改进 normalize_messages 合并时修改了原对象
transform.py:530-531
normalize_messages() 在合并同角色消息时，直接修改了 last.content：last.content = [*last.content, *msg.content]。 _pair_tool_results() 中 new_messages = list(messages) 只做了浅拷贝 — 如果传入的 messages 对象在调用后被其他代码引用，可能产生意外的共享状态。
改进方向： 在 _pair_tool_results() 中使用深拷贝，或在 normalize_messages() 入口处统一创建新消息对象。
MEDIUM 待改进 Provider httpx 客户端未显式关闭
resilient.py:112-146
create_adapter() 创建 Provider 实例时初始化了 httpx.AsyncClient，但没有提供关闭机制。各 Provider 实现了 close() 和 __aenter__/__aexit__，但 ResilientLLMAdapter 没有暴露这些方法。
改进方向： ResilientLLMAdapter 实现 close() 委托给 self._provider.close()，并实现 async context manager 协议。
MEDIUM 待改进 测试覆盖补全
目前只有 test_resilient.py (320 行) 和 test_normalize_messages.py (119 行)。transform.py（586 行纯函数）和 streaming.py（293 行解析器）缺少专门的测试文件。Provider 层（923 行）无集成测试。
LOW 待改进 CircuitBreaker.state 属性有副作用
retry.py:193-202
CircuitBreaker.state 是一个 property，读取时会检查时间并可能修改 self._state（OPEN → HALF_OPEN 转换）。这违反了 property 不应有副作用的惯例，且在调试/监控场景中可能导致意外状态变化。
改进方向： 将状态转换检查提取为显式的 _check_state_transition() 方法，property 只返回当前状态。
LOW 待改进 transform.py 接近 600 行，职责略重
transform.py
586 行是模块中最大的文件。虽然全是无状态纯函数，复杂度可控，但随着新增 Provider 会持续增长。当前可接受，若新增 Provider 可按目标拆分。
LOW 待改进 三家 Provider 的 _handle_error() 高度重复
openai_provider.py:95-119, deepseek_provider.py:133-159, anthropic_provider.py:114-139
三个 Provider 的 _handle_error() 逻辑几乎相同：读取 response body → 按 status_code 抛出对应异常。唯一差异是 provider 名称字符串。
改进方向： 提取为 handle_http_error(response, provider_name) 到 base.py 或新建 utils.py。

5. 依赖关系

依赖分析结论

  • 无循环依赖 — 依赖严格单向：Provider → transform/streaming → types/base，resilient → providers + retry + base
  • types.py 是所有模块的根依赖 — 257 行的类型定义被所有其他文件 import，变更时需注意影响面
  • Provider 之间零耦合 — openai_provider 不 import deepseek_provider，各自只依赖核心层
  • resilient.py 是唯一知道所有 Provider 的模块 — 通过 _PROVIDER_MAP 动态导入，上层代码不感知具体 Provider 类

6. 总结

LLM Adapter 模块是一个架构成熟度很高的基础设施层。核心抽象（types + ILLMAdapter）设计得当，Provider 隔离干净，装饰器模式让 retry/circuit breaker 可以独立组合。transform.py 的纯函数设计 — 586 行全是无状态转换，天然可测试，Provider 之间共享逻辑零重复。

架构亮点：统一类型系统消除了 OpenAI string|array 二义性；normalize_messages 在发送前自动修复消息格式；Anthropic Provider 完整覆盖了协议差异最大的 Provider；依赖关系严格单向、无循环依赖。

待改进：流式重试语义需要明确；Provider httpx 客户端的生命周期管理需要暴露给上层；transform.py 和 streaming.py 的测试覆盖需要补全；_handle_error 可提取为公共函数消除重复。

总体评分：8.5/10 — 成熟的 LLM 抽象层，Provider 隔离、类型系统和依赖管理设计优秀，测试覆盖和生命周期管理是主要提升空间。
