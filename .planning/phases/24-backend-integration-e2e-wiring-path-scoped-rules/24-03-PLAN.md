The function must use TYPE_CHECKING guard for the framework import to avoid circular imports at module level:
    ```python
    from __future__ import annotations
    from typing import TYPE_CHECKING
    if TYPE_CHECKING:
        from agent_framework.config.settings import Settings as FrameworkSettings
    ```

    Inside `create_settings()`:
    1. If `framework_settings` is None, return `Settings()` unchanged (current behavior, env vars and .env handle defaults).
    2. If `framework_settings` is provided, extract fallback values: `fw_model = framework_settings.model`, `fw_provider = framework_settings.llm.provider`, `fw_api_key = framework_settings.llm.api_key`, `fw_base_url = framework_settings.llm.base_url`.
    3. Build `Settings()` using pydantic-settings defaults override: pass values as kwargs to Settings constructor so pydantic-settings resolution order is: kwargs < env_file < env vars. Since pydantic-settings BaseSettings prioritizes env vars highest, passing kwargs as defaults means: if APP_LLM_API_KEY env var exists it wins; otherwise the kwarg value (from framework Settings) is used.
    4. Return the constructed Settings.

    Keep the existing `Settings` class and its `api_key_must_not_be_empty` validator completely unchanged.
