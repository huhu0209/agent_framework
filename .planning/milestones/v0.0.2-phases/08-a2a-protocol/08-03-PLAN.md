  <behavior>
  - Server 配置 api_key 时，_verify_auth 检查 scope["headers"] 中是否包含 x-api-key header
  - 无 x-api-key header 时 _verify_auth 返回 False -> 响应 401 {"error": "Missing API key"}
  - x-api-key header 值不匹配时 _verify_auth 返回 False -> 响应 403 {"error": "Invalid API key"}
  - x-api-key header 值正确时 _verify_auth 返回 True -> 请求正常处理
  - Server 未配置 api_key（None）时 _verify_auth 返回 True -> 所有请求正常处理
  - Client 构造时 api_key 参数在 httpx.AsyncClient headers 中添加 X-API-Key
  - Client 无 api_key 时不添加 X-API-Key header
  - SecretStr 包装确保 api_key 不出现在 model_dump() 或 repr() 中
  - 已有的所有测试（无认证模式）继续通过
  </behavior>

  <action>
  Per D-09: 服务级单一 API key 保护整个 A2AServer。
  Per D-10: 通过 X-API-Key header 传递。

  1. 修改 server.py：
     - 在 __init__ 中将 api_key 用 SecretStr(api_key) 包装存储（如果 api_key 非 None），存为 self._api_key: SecretStr | None。
     - 添加 _verify_auth(self, scope: dict) -> bool 方法：
       - 如果 self._api_key is None，返回 True（无认证模式）
       - 遍历 scope["headers"]（list[tuple[bytes, bytes]]），查找 key == b"x-api-key"
       - 未找到返回 False（缺失 key）
       - 值不匹配返回 False（错误 key）
       - 值匹配返回 True
     - 在 __call__ 中路由分发前调用 _verify_auth(scope)：
       - 返回 False 且缺失 key -> _send_json(send, 401, {"error": "Missing API key"})
       - 返回 False 且有 key 但错误 -> _send_json(send, 403, {"error": "Invalid API key"})
       - 注意区分两种情况：_verify_auth 需返回不同状态码。方案：_verify_auth 返回 int（0=无key, 1=有效, -1=无效），或拆分为两步检查。选择简单方案：返回 tuple[bool, int] -- (auth_ok, status_code_if_not_ok)。

  2. 修改 client.py：
     - 在 __init__ 中将 api_key 用 SecretStr 包装存储
     - 构建 httpx.AsyncClient headers 时，如果 api_key 存在，添加 {"X-API-Key": api_key.get_secret_value()}
     - 确认 httpx client 的 headers 在构造时设置（已存在于 Plan 02 的 _build_headers 方法中，添加 X-API-Key header）

  3. 更新测试文件：
     - framework/tests/test_a2a_server.py 添加认证测试组：
       - test_auth_missing_key: api_key="secret123"，请求不带 X-API-Key -> 401
       - test_auth_invalid_key: api_key="secret123"，请求带 X-API-Key: wrong -> 403
       - test_auth_valid_key: api_key="secret123"，请求带 X-API-Key: secret123 -> 正常响应
       - test_auth_no_key_configured: api_key=None，请求不带 X-API-Key -> 正常响应
       - 所有四个端点（agent-card, create-task, get-task, cancel）在有效 key 下正常工作
     - framework/tests/test_a2a_client.py 添加认证测试组：
       - test_client_sends_api_key: api_key="test-key"，验证 HTTP 请求包含 X-API-Key header
       - test_client_no_api_key: api_key=None，验证 HTTP 请求不包含 X-API-Key header
     - 确认现有测试（无认证模式）全部继续通过

  4. 先写测试（RED），再实现（GREEN），然后运行全量 A2A 测试。
