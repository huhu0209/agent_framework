# REQUIREMENTS.md — v0.0.1 彻底 Code Review

## 目标

对框架层（`framework/agent_framework/`）全部已实现代码进行系统性审查，产出结构化审查报告，修复 CRITICAL 和 HIGH 级别问题。

## 范围

**In Scope:**
- `framework/agent_framework/` 下所有 Python 源码（~7600 行）
- `framework/tests/` 下所有测试（630 个）
- 质量维度：安全、Bug、性能、架构、可维护性、测试覆盖

**Out of Scope:**
- `backend/`（全部脚手架，无可审查代码）
- `frontend/`（脚手架阶段）
- 新功能开发
- 文档/README 更新

## 需求

### R1: 安全审查（Security Review）

审查所有安全问题，按严重性分级，修复 CRITICAL 级别。

已知问题来源（CONCERNS.md）：
- 文件工具缺少路径沙箱校验
- MCP 环境变量注入
- API Key 明文存储在 provider 实例中
- Hook 命令执行任意 shell
- Permission ASK 决策未接入 HITL
- MessageBus 文件路径可预测

**验收标准：** 产出 SECURITY-REVIEW.md，修复所有 CRITICAL 问题。

### R2: Bug 修复审查（Bug Fix Review）

审查并修复所有已知 Bug。

已知 Bug：
- `agent_loop.py` 缺少 `Path` import
- `TaskManager._apply_changes` 类型注解错误
- `HITLManager.create_pending` 使用已废弃 API
- `normalize_messages` 原地变异 Pydantic 模型
- `_apply_changes` 非原子性依赖清理

**验收标准：** 修复所有已知 Bug，每个修复有对应测试验证。

### R3: 架构与设计审查（Architecture Review）

审查代码架构、设计模式、模块职责划分。

重点审查：
- `AgentLoop.__init__` 15 参数问题（God Object 倾向）
- `ToolRouter.dispatch` 4 层职责混合
- `_apply_changes` 复杂变异逻辑
- `ToolUseContext.extra` 无类型安全
- 空文件清理（`base.py`、`engine.py`、`router.py`）

**验收标准：** 产出 ARCH-REVIEW.md，记录问题和改进建议。

### R4: 性能审查（Performance Review）

审查性能问题并修复影响正确性的项。

已知性能问题：
- 同步文件 I/O 阻塞 async 事件循环
- MessageBus inbox 非原子读写
- MCP transport 逐字节读取
- TaskManager 每次查询全量扫描
- Context compaction 额外 LLM 调用

**验收标准：** 产出 PERF-REVIEW.md，修复数据安全相关项（非原子读写）。

### R5: 测试覆盖审查（Test Coverage Review）

审查测试覆盖缺口，补充关键路径测试。

已知缺口：
- TeamManager loop 行为测试不足
- 安全边界未与工具执行集成测试
- 多 Provider 切换无集成测试
- MCP transport 未对真实服务器测试

**验收标准：** 补充 HIGH 优先级缺口的测试，全部测试通过。

## 优先级

1. **R2 Bug 修复** — 最高优先级，直接影响正确性
2. **R1 安全审查** — 高优先级，影响安全性
3. **R3 架构审查** — 中优先级，记录但不一定立即重构
4. **R4 性能审查** — 中优先级，修复数据安全项
5. **R5 测试覆盖** — 补充关键路径测试

## 约束

- 每个修复独立提交，不混合多个修复
- 修复不引入新 Bug（通过测试保证）
- 重构类变更仅记录建议，不在此里程碑执行
- 所有测试必须通过
