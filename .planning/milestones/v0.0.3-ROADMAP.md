# Milestone v0.0.3: Agent 可视化平台 MVP

**Status:** ✅ SHIPPED 2026-05-31
**Phases:** 9-11
**Total Plans:** 9

## Overview

端到端链路跑通 — config → spawn → event → WebSocket → canvas render。一条链路、一个场景、一只猫。

## Phases

### Phase 9: Backend 事件系统

**Goal**: 开发者可通过 EventBus 发布/订阅 Agent 事件，WebSocket 客户端可实时接收 VizEvent 流并控制 Team 生命周期
**Depends on**: Nothing (v0.0.2 framework layer is the foundation)
**Requirements**: EVNT-01~07, WSRV-01~05
**Plans**: 3 plans

Plans:

- [x] 09-01: EventBus + VizEvent 模型 + 订阅管理
- [x] 09-02: AgentRunner 包装层（LoopEvent → VizEvent 映射）
- [x] 09-03: WebSocket 服务端（EventBus 订阅 + 推送 + 控制命令）

**Details:**

- EventBus.publish 接受 dict（VizEvent.model_dump()），有界队列 maxsize=1000 + drop-oldest
- VizEvent Pydantic BaseModel，自带 model_dump_json() 序列化
- AgentRunner 6 条映射全覆盖：step+tool_use→thinking, step+end_turn/stop_sequence→done, tool_result→tool_call, done→done, error/max_steps→error
- idle 在循环前发布，shutdown 在 finally 中发布（异常安全）
- websockets 16 asyncio API，双任务模式 recv+push，连接断开 finally 块确保 unsubscribe
- start_team/stop_team MVP 只做命令接收确认，实际 Agent 执行留后续集成

**Tests:** 14 + 12 + 7 = 33 new tests, 845 total

### Phase 10: Frontend Canvas 渲染

**Goal**: 浏览器中展示办公室场景，猫精灵根据 Agent 状态切换位置和帧动画，可视化反映 Agent 内部状态
**Depends on**: Nothing (纯前端渲染层，可与 Phase 9 并行开发)
**Requirements**: RNDR-01~07
**Plans**: 3 plans

Plans:

- [x] 10-01: PixiJS v8 应用初始化 + 办公室场景 + 点位系统
- [x] 10-02: 猫精灵 + 帧动画（idle/thinking/tool_call）+ 状态切换
- [x] 10-03: 精灵移动系统（线性插值）+ shutdown 消失动画

**Details:**

- PixiJS v8 async init pattern (new Application() + await app.init())
- 三层 Container 架构：background（场景）/ agent（精灵）/ effects（气泡）
- 几何办公室场景：2 工位（desk+monitor+chair）、茶水间（counter+cup）、门口（frame+arch+knob）
- 猫精灵：Terracotta 圆形身体 + 三角耳朵 + Near Black 眼睛，32×32 像素
- 4 种 Ticker 驱动程序化动画：drinking（idle）/ standing / typing（thinking）/ walking
- Thought bubble 效果在 effects 层，独立 Ticker 浮动动画
- lerp 移动系统：MOVE_SPEED=0.06, ARRIVAL_THRESHOLD=1.0px
- 状态→点位映射：idle→teaRoom, thinking/tool_call→desk1, shutdown→door
- shutdown 序列：走到门口 + alpha 渐隐至不可见，后续事件恢复可见性
- Design colors 集中在 DESIGN_COLORS 常量（from DESIGN.md palette）

### Phase 11: Frontend React 集成

**Goal**: 用户可通过 React 界面创建 Agent、启动/停止 Team、实时观察 Agent 状态变化和事件流
**Depends on**: Phase 9 (后端 EventBus + WebSocket), Phase 10 (Canvas 渲染层)
**Requirements**: CNFG-01~04, CONC-01~05
**Plans**: 3 plans

Plans:

- [x] 11-01: React 配置面板（创建 Agent 表单 + Team 控制 + Agent 状态列表）
- [x] 11-02: WebSocket 客户端 + reducer 状态管理 + 连接状态指示器
- [x] 11-03: React-PixiJS ref 桥接 + 事件日志列表 + 端到端集成

**Details:**

- useReducer + Context 状态管理，discriminated union actions，immutable Map updates
- ConfigForm 可折叠 Agent 配置表单（Name/Role/System Prompt）
- TeamControls Start/Stop 按钮，带 disabled 状态逻辑
- AgentStatusDot 8×8px CSS circle，颜色对应 idle/thinking/tool_call/shutdown
- useWebSocket hook：自动连接 + 指数退避重连（1s/2x/30s cap/10 retries）
- ConnectionIndicator：绿色（连接）/ 黄色（重连）/ 红色（断开）
- CanvasContainer：useRef 命令式 PixiJS 桥接，isInitialized ref 防 StrictMode double-mount
- EventLog：256px 可滚动容器，timestamp + 彩色 type badge + agent name，自动滚到底部
- 内联样式替代 Tailwind utility classes（DESIGN.md 自定义颜色更自然）
- 所有组件 TypeScript 编译零错误，Vite 生产构建成功

## Milestone Summary

**Key Decisions:**

- Decision: PixiJS v8 (非 Phaser) — Rationale: 纯渲染引擎无游戏框架开销
- Decision: websockets 库 (非 FastAPI WebSocket) — Rationale: 独立于 FastAPI，纯 asyncio
- Decision: useRef 命令式桥接 (非 React-PixiJS 库) — Rationale: 零依赖，单向数据流
- Decision: 有界队列 drop-oldest — Rationale: 防止慢消费者内存溢出
- Decision: 内联样式 (非 Tailwind) — Rationale: DESIGN.md 自定义颜色更自然
- Decision: useReducer+Context (非 Redux) — Rationale: MVP 范围不需要复杂状态管理
- Decision: flat frontmatter Agent 配置 — Rationale: 不引入 pyyaml 依赖
- Decision: Phase 9 和 Phase 10 并行开发 — Rationale: 前后端解耦

**Issues Resolved:**

- Phase 9: EVNT/WSRV 12 项需求全部实现并测试通过
- Phase 10: PixiJS v8 API 迁移（v7→v8 API 差异处理）
- Phase 11: StrictMode double-mount 问题通过 isInitialized ref 解决

**Issues Deferred:**

- EventBus topic 过滤机制 (v0.0.4+)
- 事件持久化到文件/数据库 (v0.0.4+)
- 多动物形象选择 (v0.0.4+)
- 消息气泡飞行动画 (v0.0.4+)
- 拖拽编排 Agent 工作流 (v0.0.4+)

**Technical Debt Incurred:**

- start_team/stop_team 只做命令接收确认，实际 Agent 执行留后续集成
- 前端单元测试缺失（第一期验证端到端链路）
- 移动端未适配
