# Milestone v0.0.2: Agent 扩展与编排

**Status:** SHIPPED 2026-05-29
**Phases:** 6-8
**Total Plans:** 9

## Overview

从单一 ReAct Agent 扩展为多类型 Agent 体系，新增编排引擎和 A2A 协议支持。框架从"单 Agent 循环"进化为"多类型 Agent + 编排 + 跨 Agent 通信"。

## Phases

### Phase 6: Agent 类型扩展

**Goal**: 框架支持多种 Agent 类型，每种通过统一的 Agent 接口暴露，且现有 687 测试全部通过
**Depends on**: Phase 5 (v0.0.1 baseline)
**Requirements**: AGENT-01~05, PLAN-01~05, REFL-01~04
**Plans:** 3/3 plans complete

Plans:
- [x] 06-01: Agent ABC + AgentEvent 基础设施（AGENT-01~05）
- [x] 06-02: Plan-and-Solve Agent（PLAN-01~05）
- [x] 06-03: Reflection Agent（REFL-01~04）

**Success Criteria:**
1. AgentEvent 统一事件模型可用，支持 step/tool_result/done/max_steps/error 五种类型
2. AgentLoop 实现了 Agent 接口，现有 687 测试全部通过（零回归）
3. PlanAndSolveAgent 可以接收任务、生成计划、逐步执行，偏离时重新规划（最多 2 次），空计划时 fallback 到 ReAct
4. ReflectionAgent 可以执行任务、自我评估输出质量、改进不满意的结果（最多 2 轮）
5. 所有新增 Agent 类型通过各自的测试套件验证

### Phase 7: 编排引擎 + 配置化 + 搜索

**Goal**: 框架具备 Agent 编排能力、声明式配置能力和真实搜索能力
**Depends on**: Phase 6
**Requirements**: ORCH-01~05, CONF-01~04, SRCH-01~03
**Plans:** 3/3 plans complete

Plans:
- [x] 07-01: OrchestratorEngine 编排引擎（ORCH-01~05）
- [x] 07-02: Agent 配置化（CONF-01~04）
- [x] 07-03: 真实搜索工具（SRCH-01~03）

**Success Criteria:**
1. OrchestratorEngine 可以评估任务复杂度（启发式规则），将简单任务路由到 ReAct、复杂任务路由到 Plan-and-Solve
2. 执行偏离时触发计划修正，每条 Agent 链最多 3 个 Agent
3. Agent 配置可以通过 .md 文件声明式定义，agent_from_config() 能创建完整可运行的 Agent 实例
4. 搜索工具调用 Tavily API 返回真实结果，并发受 Semaphore 控制
5. agent_factory 模式允许编排引擎按需创建新 Agent 实例

### Phase 8: A2A 协议

**Goal**: 框架支持 A2A 协议，本地 Agent 可暴露为 HTTP 端点，远程 Agent 可作为工具调用
**Depends on**: Phase 6
**Requirements**: A2A-01~06
**Plans:** 3/3 plans complete

Plans:
- [x] 08-01: A2A 数据模型 + AgentCard（A2A-01, A2A-02）
- [x] 08-02: A2AServer + A2AClient 实现（A2A-03, A2A-04, A2A-05）
- [x] 08-03: API-key 认证（A2A-06）

**Success Criteria:**
1. AgentCard 数据模型可描述 Agent 能力（name, description, url, version, capabilities）
2. A2AServer 可将本地 Agent 暴露为 HTTP 端点
3. A2AClient 可向远程 Agent 提交任务、轮询状态、取消任务
4. 同步模式（POST + 轮询）完整可用
5. 所有 A2A 通信受 API-key 认证保护

## Milestone Summary

**Key Decisions:**
- Agent ABC 面向接口编程，不约束 __init__ 签名
- LoopEvent 继承 AgentEvent 向后兼容，plan 字段在 data dict 中传递
- PlanAndSolveAgent replan 硬上限 2 次，防止无限循环
- ReflectionAgent 改进轮次硬上限 2 次，不让 LLM 自行决定
- OrchestratorEngine 使用启发式规则评估复杂度（无额外 LLM 调用）
- Agent 配置使用 flat frontmatter（.md 文件），不引入 pyyaml
- A2A 使用纯 ASGI 实现（不依赖 FastAPI），同步模式优先
- API-key 认证使用 SecretStr + X-API-Key header

**Issues Resolved:**
- AgentLoop 硬编码为唯一 Agent 类型的架构限制
- 搜索工具使用 mock 数据无法提供真实搜索能力
- 缺乏跨 Agent 通信协议
- 缺乏声明式 Agent 配置能力

**Issues Deferred:**
- A2A 流式模式（SSE streaming）— 后续扩展
- A2A 异步模式（Webhook callback）— 后续扩展
- DAG 调度模式（LLMCompiler / ReWOO）— 后续扩展
- LLM 动态路由（基于任务语义）— 后续扩展

**Technical Debt:**
- v0.0.1 遗留 14 项 tech debt（all LOW），详见 v0.0.1-MILESTONE-AUDIT.md
- OrchestratorEngine 复杂度评估为简单启发式（可升级为 LLM 动态路由）
